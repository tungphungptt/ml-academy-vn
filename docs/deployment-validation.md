## Network diagnosis and boundaries

The initial Prisma checksum 403 was network policy, not schema validation.
A cloud configuration draft now allows `binaries.prisma.sh`, `nextjs.org` and
`render.com`, preserving package-manager presets. Subsequent requests succeeded
and engines were fetched with checksum/TLS verification intact. To retain this
cloud configuration for future tasks, review/save the draft in environment
settings and publish the cloud environment; this does not create/deploy Render.

Docker's initial failure was DNS inside the build network; forwarding the
existing proxy and its resolved hostname fixed that. npm then reported a
self-signed CA chain. Mounting the platform-provided CA as optional BuildKit
secret `extra_ca` restored normal certificate verification. The added proxy CA
and proxy values are not baked into the image, and no application secret value
is embedded in the Blueprint.

The dependency tree has no invalid peer versions. npm 11 lists two optional
Sharp WASM packages as extraneous even after a clean `npm ci`; both have pinned
versions/integrities in the lockfile, and native Sharp 0.35.5 loads correctly.
No new direct platform-specific dependency was added to conceal that npm note.

- The original validation phase did not publish changes. At the start of the
  final pre-commit review, `git fetch origin` still resolved `origin/main` to
  the base commit above. The user subsequently authorized commit/push to `main`;
  verify the resulting remote SHA before creating a Blueprint. No Render
  service, deployment, cost, or production migration is part of that Git step.
- Starter compute and its 1 GB persistent disk are paid. SQLite is one instance;
  disk-backed deploys have downtime. Load capacity and Render's live builder,
  public TLS routing and service provisioning have not been tested here.
- For existing production data, first back up/restore a copy, compare the schema,
  baseline only after an exact match, and explicitly import backed-up Markdown
  edits before replacing an old container. Tests of this process used separate
  test databases only. See [the runbook](render-deployment.md).
- Future production schema changes require reviewed migrations and operator-led
  maintenance with disk access. Startup deliberately stops on pending migrations.
  Render pre-deploy commands cannot access the persistent disk.
- Prisma stays at 5.20.0 as requested; a future Prisma upgrade is a separate
  compatibility/migration decision.
- Turbopack reports broad dynamic-filesystem tracing for content/override paths.
  This build uses a full Docker image, not a minimal standalone trace; all
  packaged content is intentionally present and external overrides are mounted
  at runtime. Builds and functional checks pass. Image/tracing optimization
  remains possible; no warning/validation was disabled to hide it.
- CSP remains report-only (existing behavior). External source-link checks,
  full Pyodide/CDN behavior and all ML/PyTorch notebooks were not part of these
  deployment checks. Those checks were not represented as passed.
